# 第六阶段：长期运行稳定性与堆状态有界性

## 目标与实现

本阶段检验事件长期运行时的失效 Min-Heap 记录增长、压缩后的堆约束、重建耗时和内存变化。对照包括 Expiration-indexed、无压缩 Compact、默认压缩 Compact、候选阈值 Compact、默认压缩 Optimized Compact、候选阈值 Optimized Compact。阈值分别为不压缩、`H > max(64, 2A)`、`H > max(128, 3A)`。

未增加 Manager。长期负载由 `benchmark/long_run_heap_stability.py` 按固定种子逐事件生成，不将整条事件流放入内存；每种策略/规模/重复由独立 Python 子进程运行。事件流包含成功匹配、重复 start、未完成实例、身份交错/复用、截止点匹配和窗口过期。主体事件时间保持在 t=0，以模拟 watermark 暂不推进时的高密度输入；尾部在 t=30 完成截止边界匹配，并在 t=31 触发全局过期。事件时间非递减。

规模为 10,000、100,000、500,000，每格 3 次重复，共 54 个隔离进程运行。每 10,000 个事件采样 A、H、H-A、累计压缩数、累计压缩时间、处理数、进程当前/峰值工作集和 Manager 对象图估计；另在流尾过期前采样一次。峰值堆长度逐事件准确更新。所有策略的事件流哈希、逐事件检测与活动数摘要、最终和峰值活动数一致；边界匹配有显式断言。

## 正确性问题及修复

实验前的最小复现发现一个边界缺陷：当 64 条失效记录后创建第 65 个活动实例时，压缩可能在该实例第一次 tick、`Window.start_time` 初始化之前触发。重建若只从已初始化的 Window 推算截止时间，会遗漏新实例的堆记录，之后无法由堆触发其过期清理。

现有 Compact 和 Optimized Compact Manager 现将创建时计算的绝对 `expire_at` 保存在实例上，并在重建时使用该截止时间。增加的回归测试验证该实例记录保留且在 t=32 正确过期；另有逐事件检查确保压缩后满足对应堆阈值。该修复没有新增 Manager，也没有改动 Expiration-indexed、Context-indexed 或 Baseline。

## 吞吐与压缩代价

默认策略累计压缩次数随规模从 55 增至 498、2,467 次，累计重建时间从约 0.62 ms 增至 6.72 ms、32.25 ms。候选策略压缩次数从 26 增至 249、1,242 次，累计时间从约 0.35 ms 增至 3.64 ms、18.15 ms。重建总时间随事件规模增长；在本负载中它占 Optimized 总处理时间比例约 1.2%–1.3%（默认）和约 0.7%–0.8%（候选）。这说明单次重建是 O(A)，累计代价取决于重建频率及当时活动实例数。

500,000 事件时，未压缩吞吐约 39,699–41,440 事件/秒，压缩版本约 181,584–202,009 事件/秒。此差异是在失效记录堆增长到约 160,000 条的刻意压力流上观测到的；它不能外推为一般流上压缩总能提高吞吐。压缩通过增加重建工作控制 H，同时避免后续堆操作长期面对不断增长的陈旧记录；此次实验没有拆分每次 heap push/pop 的独立成本。

默认阈值的堆更小，但重建更多；候选阈值降低重建次数和重建总时间，堆记录上界及 Manager 状态占用略高。长期内存收益在本次独立进程中可观察：500k 时，无压缩峰值 Manager 对象图估计约 22.8 MiB，压缩版约 71–83 KiB；整个子进程的峰值工作集增量从约 65 MiB 降到约 0.8–0.9 MiB。进程指标包含解释器、导入、运行时和分配器缓存，不能解释为 Manager 独占内存；对象图估计也不是 RSS/真实分配器占用。

## 结论、边界与下一步

**有实验支持的结论：**在延迟推进事件时间、持续成功完成并积累失效记录的可复现负载中，无压缩堆状态随事件数增长；默认和候选压缩将堆峰值保持在各自阈值附近，且尾部过期语义与其他实现一致。独立子进程中的 Manager 状态估计和进程峰值增量均显示明显下降。压缩累计耗时随事件数增加，但在该压力流中占总处理时间比例较低。

**尚未证实：**真实线上流是否会长时间停滞 watermark；不同 A/H 比例、窗口长度、硬件与 Python 分配器下的最优阈值；进程峰值工作集收益能否在生产负载中重现；压缩在一般负载下的净吞吐影响。

**局限：**事件流为合成且主体事件时间集中在 t=0，属于针对陈旧堆积的压力场景；每项只有 3 次重复；只在单一 Windows 环境运行，未记录 CPU/系统构建/电源状态；进程内存值含解释器及分配器开销；状态对象图大小是近似值。后续应加入真实回放、不同 watermark 推进频率、更多重复和跨进程置信区间，并记录硬件元数据。
